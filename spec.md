# Spec: Screenlog

## Objective

Screenlog is a personal watch-logging app that keeps Letterboxd's movie logging/rating experience while giving **TV shows full, equal support** (shows are not a bolted-on afterthought — they get the same search/log/rate experience as movies).

**User story:** As a user, I want to search for movies and TV shows, rate them (both an overall rating for a show and a separate rating per season), optionally leave a written review, record when I watched something, and keep unwatched titles in a watchlist.

**Out of scope for MVP (deferred to v2):**
- Social features (following other users, activity feed, likes/comments on reviews) — the architecture will leave room for this later, but it won't be built now.
- Custom lists (Letterboxd's "Lists" feature, e.g. "My Top Sci-Fi Movies").
- Episode-level logging — TV granularity is **show + season**, no episode level.

**Definition of done:** A user can sign up and log in, search TMDB for movies/shows, mark something as watched with a rating (show + season level for TV), write an optional review, record the watch date, add/remove items from a watchlist, and view their own history (diary) in chronological order.

## Tech Stack

- **Frontend:** Next.js 16 (App Router), React 19, TypeScript (strict mode)
- **Styling:** Tailwind CSS 4
- **Backend/DB:** Supabase (Postgres + Auth + Row Level Security)
- **Auth methods:** Email/Password + Google OAuth (via Supabase Auth)
- **External data source:** TMDB API (movie/show/season metadata, posters, cast, descriptions)
- **Deployment:** Vercel

> ⚠️ This repo runs Next.js 16. Per `AGENTS.md` (auto-regenerated by `next dev` on every run), this version may differ from training-data Next.js APIs/conventions, so `node_modules/next/dist/docs/` must be checked before writing code.

### High-level data model (detailed schema to be finalized in the Plan phase)

- `profiles` — 1:1 with Supabase `auth.users`, holds public profile info (username, avatar)
- `movie_logs` — user_id, tmdb_movie_id, rating (0.5–5), review (nullable text), watched_date, rewatch (bool)
- `show_logs` — user_id, tmdb_show_id, rating (0.5–5, overall show rating), review (nullable text)
- `season_logs` — user_id, tmdb_show_id, season_number, rating (0.5–5), review (nullable text), watched_date
- `watchlist` — user_id, tmdb_id, media_type (`movie` | `tv`), added_at

RLS on every table: a user can only read/write their own rows (no social visibility, no public profile page in MVP).

## Testing Strategy

- **Unit/component:** Vitest + React Testing Library — rating logic, TMDB data mappers, form validation, and other pure logic/components.
- **Integration:** Local Supabase (CLI) tests that verify RLS policies and queries behave correctly.
- **E2E:** Playwright — critical flows: sign up/login, movie/show search, creating a log (rating + review + date), season rating, adding/removing from watchlist.
- Coverage target: not chasing 100%; core business logic (rating calculations, RLS-dependent queries, auth flow) must be tested.

## Git Workflow

- **Branch naming:** `feat-id/example-branch` (type-id/description format; `id` is the task/issue number, e.g. `feat-12/season-rating`)
- **Commit naming:** `feat(id): example commit` (conventional commits with the task id as scope, e.g. `feat(12): add season rating component`)

## Boundaries

- **Always:**
  - Every Supabase table has an RLS policy defined
  - TMDB API key and Supabase service role key stay server-side (env vars) only, never exposed to the client
  - `npm run lint` and `tsc --noEmit` pass clean before commits
  - `.env.local` stays gitignored
  - Branch and commit names follow the Git Workflow format above
- **Ask first:**
  - Supabase schema/migration changes
  - Adding a new dependency
  - Changing the auth flow (e.g. adding a new OAuth provider)
  - Expanding TMDB API usage (e.g. new endpoints)
- **Never:**
  - Commit `.env*` files or secrets
  - Use old/known Next.js patterns without checking `node_modules/next/dist/docs/` first
  - Remove failing tests without approval

## Success Criteria

- [ ] User can sign up and log in with email/password or Google
- [ ] User can search TMDB for movies and shows and see results
- [ ] User can log a movie with a 0.5–5 rating, optional review, and watch date
- [ ] User can give an overall rating to a show
- [ ] User can rate each season of the same show separately
- [ ] User can add/remove movies and shows from a watchlist
- [ ] User can view all their logs in chronological order (by watch date) on their own diary/history page
- [ ] All data access is scoped to the user via RLS (no user can see or modify another user's data)
